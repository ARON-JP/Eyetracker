# GazeDot

Webカメラだけで動く **視線オーバーレイ** アプリです。画面のどこを見ているかを推定し、
配信に映る「視線の円」をクリックスルーのオーバーレイとして表示します。

Beam Eye Tracker の Demo やそのバイナリには一切依存していません（独自実装・別アプリです）。
カメラ映像はすべて PC 内で処理され、外部送信はありません。

---

## できること

- Webカメラ（USB / スマホ仮想カメラ）だけで視線推定
- 5点 / 9点クリック式キャリブレーション（中央から開始）＋任意の精度チェック
- 顔の yaw / pitch / roll を基準姿勢に合わせて補正し、追跡を止める許容角度を個別に調整
- 正面リセットと画面端4点の簡易補正で、顔の位置ずれによる画面座標のずれを再調整
- 透明な紫色の円形トレイルと多層ネオングロー。重なる円の内側の輪郭を除去
- サイズ・輪郭の太さ・色・不透明度・グロー・トレイル持続時間・速度連動サイズを調整
- OBS等のキャプチャ互換性がある場合に、Windowsの画面キャプチャからオーバーレイを除外
- カメラ番号・解像度・FPS・ミラー表示・使用する目（両目/左目/右目）を設定してその場で再接続
- 頭部姿勢と視線座標のスムージングを別々に設定
- OBS 確認用の「テスト表示」
- まばたき／顔の見失い時は減光→自動非表示（ちらつき防止）
- One Euro Filter による「静止時はピタッ、サッケード時は追従」の平滑化
- 更新頻度と微小移動のデッドゾーンを設定し、小刻みな揺れを抑制
- マルチモニター対応（キャリブレーションする画面を選択）
- プロファイル保存（ユーザーごと・照明環境ごとに切り替え）
- グローバルホットキー（他アプリがフォアグラウンドでも操作可能）

## 必要環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 (64bit) |
| Python | 3.10 – 3.12（3.11 推奨 / 3.14 は MediaPipe 非対応） |
| カメラ | 640x480 / 30fps 以上 |
| メモリ | 約 300–450 MB |
| GPU | 不要（CPU のみ。4コア以上推奨） |

## セットアップ

初回だけ `run.bat` をダブルクリックしてください（自動で venv 作成・依存インストール・
顔モデル取得を行います）。手動でやる場合:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

モデル（`models/face_landmarker.task`, 約 3.6MB）は
[MediaPipe 公式](https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task)
から取得します。

## 使い方

1. `run.bat` で起動（コンソール付きで確認したいときは `run_debug.bat`）
2. パネルでキャリブレーション点数（5点 / 9点）を選び、「キャリブレーション (F9)」を押す
3. 全画面の **点をマウスでクリック** し、そのまま点を見つめる（頭は動かさない）。端に近い校正マーカーは画面の0% / 100%位置として学習されます
   - まん中の点から始まり、選んだ点をクリックして見つめると順に進みます
   - クリックすると 0.12 秒で位置が安定し、0.8 秒サンプルを集めて自動で次の点へ
   - サンプルが足りないときは「もう一度クリック」と表示されます
   - ESC でいつでもキャンセル
4. 完了すると推定誤差（キャリブレーション点ごとの交差検証）が表示されます
5. 画面に透明な紫色の円形トレイルが出ます。パネルでサイズ・輪郭・グロー・持続時間を調整
   - 「テスト表示」で画面中央に5秒間表示して見た目を確認できます
6. 顔の向きを変えたときは、正面を向いて「正面リセット」を実行します
7. 顔の位置や視線位置がずれたときは、「画面端を簡易補正」を実行し、画面端近くに表示される4点を順にクリックして見つめます。校正データは画面の端（0/100%）に対応します
8. ショートカット欄のキー表示ボタンを押してから任意のキー、または Ctrl / Alt / Shift と組み合わせたキーを押すと、機能ごとのキーを割り当てられます

### ホットキー

| キー | 動作 |
|---|---|
| F9 | キャリブレーション |
| Alt+C | 正面リセット（初期割当。設定で変更可能） |
| F5 | 画面端を簡易補正 |
| F10 | オーバーレイ表示 ON/OFF |
| F8 | カメラプレビュー ON/OFF |
| F7 | パネルを最小化 / 復帰 |
| F12 | 終了 |

`config.json` の `hotkeys` で変更できます。

### OBS / 配信での使い方

- OBS の **「画面キャプチャ」**（Windows 10 以降は Windows Graphics Capture 推奨）で円が映ります
- パネルの「テスト表示」を押すと、キャリブレーション前でも円が5秒間表示され、
  OBS 側に取り込めているかをその場で確認できます
- 「ゲームキャプチャ」には映りません（ゲームの描画ではないため）
- ゲーム側は **ボーダーレスウィンドウ / ウィンドウモード** にしてください
  （排他フルスクリーンではオーバーレイは表示されません）
- 円はクリックスルーなので、ゲームの操作を邪魔しません
- 「画面キャプチャからオーバーレイを除外」を使うと、対応するWindowsキャプチャではデスクトップ上に表示したまま録画から除外できます。OBSのキャプチャ方式によって結果は異なるため、テスト表示で確認してください

## 仕組み

```
カメラ 30fps ──> MediaPipe Face Landmarker (478点, 虹彩込み)
                     │
                     ├─ 虹彩中心 / 目頭・目尻・上瞼・下瞼 からの相対位置（左右2眼）
                     ├─ solvePnP による頭部姿勢（yaw / pitch / roll）
                     └─ 顔中心・両眼間距離
                     │
              17次元の特徴量
                     │
        リッジ回帰（ユーザーごとに学習, 正則化は点ごとのLOOで自動選択）
                     │
              正規化画面座標
                     │
          One Euro Filter（速度適応の平滑化）
                     │
         Win32 レイヤードウィンドウ（透明な円形トレイル / 多層グロー / クリックスルー）
```

- キャリブレーションは点ごとに外れ値（まばたき・サッケード混入）を MAD で除去
- 表示される誤差は **点ごとの交差検証**（1点を抜いて残りで学習→抜いた点を予測）の画素RMSE。
  学習データへの当てはまりではないため、実際の追従に近い値になります
- 平滑化は `filter.responsiveness`（0=生, 100=強い）。`filter.update_hz` は新しいトラッカーフレームの処理上限、`filter.deadzone_px` は微小移動を無視する距離です
- `filter.head_responsiveness` は頭部姿勢補正の平滑化。視線出力のスムージングとは別々に設定できます
- 片目追跡は選択した眼の特徴を両方の入力スロットに揃えて回帰器へ渡します。両目/片目の切替、カメラ、解像度を変えた後は再キャリブレーションが必要です
- 正面リセットは現在の顔角度を新しい基準にし、元のキャリブレーション姿勢に対して姿勢特徴を補正します
- 画面端の簡易補正は左右・上下の4点から、出力位置の倍率とオフセットを再推定します
- トレイルは時刻付きの視線履歴から生成します。速度で円サイズを変え、期限切れでフェードし、円群の合成外周だけを描くため重複箇所に内側の線を残しません
- オーバーレイは軌跡範囲に合わせた可変サイズのウィンドウにし、長い軌跡だけ内部解像度を下げて再拡大することで描画負荷を抑えます
- 頭部が `filter.max_yaw` / `max_pitch` / `max_roll` を超えたら円を止めます（許容角度はパネルで設定）

### Beam Eye Tracker について

Beam の公開セットアップ資料で説明されているカメラ配置・傾きの確認、ガイド付き校正、快適な正面姿勢へのリセンターを参考に、独自のカメラ視線回帰・顔姿勢補正・画面端校正を実装しています。Beam の非公開内部処理を推測・複製したり、Beam SDK に依存したりはしていません。公開資料では、頭部を自然に動かしつつ視線を主に使う校正や、画面端では精度が下がる可能性も案内されています。

- [Beam セットアップ](https://beam.eyeware.tech/get-started/)
- [Beam ホットキー（リセンター）](https://beam.eyeware.tech/hotkeys/)
- [Beam SDK / 公開仕様](https://beam.eyeware.tech/developers/)

## 設定（config.json）

```jsonc
{
  "monitor": 0,              // 表示するモニター番号（0始まり）
  "profile": "default",
  "calibration_points": 5,   // 5 または 9
  "show_overlay": true,
  "show_preview": false,
  "camera": { "index": 0, "width": 640, "height": 480, "fps": 30, "mirror": true },
  "overlay": {
    "radius": 30, "thickness": 3,
    "color": "#7B61FF", "opacity": 1.0, "shadow": true,
    "glow_intensity": 0.72, "glow_radius": 16,
    "trail_duration_ms": 360, "trail_speed_scale": 0.65,
    "dim_after_ms": 140,    // まばたき後に薄くするまで
    "hide_after_ms": 900    // 顔を見失ってから消すまで
  },
  "filter": {
    "responsiveness": 55,   // 0..100
    "deadzone_px": 1.8,
    "update_hz": 30,
    "max_yaw": 38, "max_pitch": 30, "max_roll": 35
  },
  "hotkeys": { "calibrate": "F9", "reset_frontal": "F6",
               "edge_calibration": "F5", "toggle_overlay": "F10",
               "toggle_preview": "F8", "toggle_panel": "F7", "quit": "F12" }
}
```

## 精度を上げるコツ

- **明るさ**: 顔の正面から光を当てる。逆光は苦手
- **距離**: カメラから 50–70cm、顔が画面の 1/3 以上を占めるように
- **姿勢**: 通常キャリブレーション中は頭を固定。姿勢を変えたら正面リセットし、画面座標がずれた場合は端点補正。大きく向きを変える運用では再キャリブレーションが必要になる場合があります
- **メガネ**: 反射が強いと虹彩がずれます。可能なら外すか、角度を変える
- **再キャリブレーション**: 照明を変えたら必ずやり直す（プロファイルを分けると便利）
- **滑らかさ**: 追従が遅い → スライダーを左へ / 震える → 右へ

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 顔が「未検出」のまま | 他のアプリ（Discord / Teams / OBS / Beam など）がカメラを掴んでいないか確認。`config.json` の `camera.index` を 0→1 に変えて試す |
| 起動時に「カメラを開けません」 | 上と同じ。USB を挿し直す |
| 円が出ない | まず「テスト表示」で出るか確認。出れば F10 とキャリブレーション済みかを確認。出なければオーバーレイ設定ミスか、排他フルスクリーンのゲームが前面にいる |
| 追従が大きくズレる | 「精度チェック」で誤差を確認。明るい場所で再キャリブレーション。メガネを外す。カメラに近づく |
| キャリブ中に「サンプル不足」 | 顔が暗い・小さい・マスク等で隠れている。明るくして、点を見たままもう一度クリック |
| カクつく | 他のアプリの CPU 使用率を下げる。`camera.fps` を 60 にすると滑らか（対応カメラのみ） |
| プレビューが黒い | カメラが他アプリに占有されている、またはスマホ仮想カメラ側が未接続 |

## 制限事項

- ゲームへの直接出力（TrackIR / Freetrack / vJoy）は未実装。画面オーバーレイ専用です
- 頭部トラッキング（6DoF）ではなく、あくまで注視点の推定です
- 赤外線カメラではないため、暗所・強い逆光では精度が落ちます
- 眼鏡のフレーム反射や、前髪で目が隠れると虹彩が取れません
